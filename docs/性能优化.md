# 体积与内存优化记录

基线是 0.9.1 发布时的安装包与本机构建。所有数字都在本机实测，测量方法写在各节下面。

## 结果

| 指标 | 基线 | 现在 | 变化 |
| --- | --- | --- | --- |
| Windows 安装包 | 146 MB | 109.6 MiB（114.9 MB 十进制） | −25% |
| `app.asar` | 35 MB | 15.5 MB | −56% |
| 渲染资源目录 | 22 MB | 14 MB | −36% |
| 首屏 `index-*.js` | 11.4 MB（gzip 2.2 MB） | 1.12 MB（gzip 0.33 MB） | −90% |
| Electron 语言包 | 49 MB | 1.2 MB | −97% |
| 空界面 renderer 内存 | 124 MB | 103–104 MB | −17% |
| 冷启动到 appReady | 1.87 s | 1.28 s | −32% |
| `mcp_audit` 表 | 25108 行 / 7.7 MB | 5000 行 | 上限生效 |

安装包用 `electron-builder --win nsis` 本机实测；内存用 PowerShell 读 WorkingSet，冷启动空界面 15 秒后连续采样三次。

## 第二轮：RDP 自研后的体积与内存（2026-11-09）

| 指标 | 第一轮后 | 现在 | 变化 |
| --- | --- | --- | --- |
| Windows 安装包 | 115.45 MB 十进制（110.1 MiB） | **113.0 MB（107.8 MiB）** | −2.45 MB |
| `app.asar` | 18 MB | 11 MB | −7 MB |
| RDP 懒加载 JS | 7.72 MB（wasm 以 base64 内联） | 0.08 MB + 0.06 MB | 基本归零 |
| RDP wasm | 内联在 JS 里 | 5.69 MB 独立资源 | `extraResources` 分发 |
| 打包后 resources 目录 | 55 MB | 39 MB | −16 MB |
| 打开一个 1184×794 RDP 后的内存（dev） | 约 1.0 GB（renderer 217 / GPU 597） | **612 MB（renderer 165 / GPU 258）** | renderer −52 MB |
| 空界面内存（dev，重启后 14 s） | 521 MB | 537 MB | 基线波动，无退化 |

改动：

- `scripts/patch-ironrdp-vendor.mjs`（`npm run vendor:patch`）：把 vendor 里 base64 内联的 wasm 拆成 `ironrdp_web_bg.wasm`，初始化改成读全局 `__TERMPILOT_IRONRDP_WASM__`。渲染进程不能 `fetch(file://)`，所以由主进程 `desktop:rdp-wasm` 把字节读出来经 IPC 传入；wasm 实例化后立即删掉全局引用，不再常驻 5.7 MB。
- 关闭 RDP 视图时把 canvas 的宽高归零，让 Chromium 尽快回收这块 surface。
- `files` 排除 node-pty 的 MSVC 中间产物（`*.iobj/*.ipdb/*.obj/*.lib/*.exp/*.tlog`、`build/deps`、`build/obj`），resources 55 → 39 MB；打包后用本机终端实测 pty 正常。
- electron-builder `compression: "maximum"`。
- 新增 MCP `desktop_close`，并让 `connection_close` 真正关掉桌面标签（之前只关桥接，标签和渲染进程都留着，RdpView 还会自动重连）。实测关标签后：主进程 156.5 → 141.8 MB、GPU 264.9 → 216.2 MB、renderer 166.1 → 153.5 MB，合计 643.5 → 567.3 MB。

安装包测量：`release-rdp3`（只做 wasm 外置）115,001,093 字节，`release-rdp4`（再加 node-pty 裁剪与最高压缩）112,998,477 字节。
